# 01 Requirements

## 1. 文档目的

本文档定义 Project25 v1.0 计划实现的系统能力和行为边界，用于指导后续架构设计、功能实现与测试验证。

本文档描述系统“必须做什么”，不规定具体模块、Task、函数和外设实现方式。

## 2. v1.0 系统范围

Project25 v1.0 计划实现一个单轴闭环运动控制节点。

系统使用增量式编码器获取运动反馈，通过 Homing 建立机械参考坐标，并支持速度控制、位置控制、软硬件限位、运动规划、故障处理、Modbus RTU 通信、参数管理和系统健康监控。

## 3. 不在 v1.0 范围内

以下内容不属于 v1.0 范围：

- BLDC 和 FOC
- 电流闭环
- CANopen 和 EtherCAT
- 多轴联动
- Linux 和 Qt 上位机
- 复杂机械滑台
- 更换 MCU

## 4. 功能需求

### 4.1 系统启动与运行状态

| ID | 需求 | 验证思路 |
| -- | -- | -- |
| SYS-001 | 系统上电后应完成必要初始化，并保持电机输出关闭，等待合法操作命令 | 上电后观察状态和 PWM 输出 |
| SYS-002 | 系统应能够对外提供当前运行状态 | 通过调试串口或通信接口读取状态 |
| SYS-003 | 系统未建立有效机械坐标前，不应接受普通位置运动命令 | 上电后不执行 Homing，发送位置命令并观察系统响应 |

### 4.2 Homing

| ID | 需求 | 验证思路 |
| -- | -- | -- |
| HOME-001 | 系统应能够利用 HOME/MIN 硬件开关建立机械参考坐标 | 从不同初始位置执行 Homing，检查坐标是否建立 |
| HOME-002 | Homing 成功后，系统应记录当前坐标有效 | Homing 完成后读取 Homed 状态 |
| HOME-003 | Homing 未成功时，系统不得报告机械坐标有效 | 人为阻止 Homing 完成，检查 Homed 状态 |

### 4.3 运动控制

| ID | 需求 | 验证思路 |
| --- | --- | --- |
| MOT-001 | 系统应支持带方向的速度闭环控制 | 分别设置正向和反向目标速度，观察实际速度 |
| MOT-002 | 系统应支持基于机械坐标的位置闭环控制 | Homing 后设置目标位置，观察最终位置 |
| MOT-003 | 系统应限制运动过程中的最大速度和最大加速度 | 记录位置与速度曲线，检查是否超过设定限制 |
| MOT-004 | 系统到达目标位置后，位置误差应保持在允许范围内 | 记录目标位置和实际停止位置 |

### 4.4 限位与故障

| ID | 需求 | 验证思路 |
| --- | --- | --- |
| SAFE-001 | 正常运动触发 MIN 或 MAX 硬件限位时，系统应停止电机并报告故障 | 运行中触发对应微动开关 |
| SAFE-002 | 目标位置超出软件位置范围时，系统应拒绝该命令、禁止电机开始运动，并报告软件限位错误 | 设置超出软限位的目标位置，检查电机输出和错误状态 |
| SAFE-003 | 系统进入 FAULT 后应关闭电机输出 | 注入可验证故障并检查 PWM |
| SAFE-004 | Fault Reset 后系统不得自动继续故障前的运动命令 | 运动中触发故障，然后执行 Fault Reset |

### 4.5 通信

| ID | 需求 | 验证思路 |
| --- | --- | --- |
| COMM-001 | 外部控制器应能够执行 Enable、Disable、Home、模式设置、目标速度设置、目标位置设置和 Fault Reset | 通过 Modbus 主站逐项发送命令并观察系统响应 |
| COMM-002 | 外部控制器应能够读取实际位置、实际速度、运行状态、Fault Code 和 Homed 状态 | 通过 Modbus 主站读取数据并与系统实际状态比较 |
| COMM-003 | 运动过程中通信超过规定时间无有效控制命令时，系统应停止电机并报告通信超时故障 | 运行中断开通信并观察停止时间和故障状态 |

### 4.6 参数管理

| ID | 需求 | 验证思路 |
| --- | --- | --- |
| PARAM-001 | 系统应在应用参数前检查参数是否处于允许范围内 | 写入超出范围的参数并观察系统响应 |
| PARAM-002 | 需要持久保存的参数应在重新上电后恢复 | 修改参数、断电重启并重新读取 |
| PARAM-003 | 参数数据无效时，系统不得直接使用该数据控制电机 | 模拟无效参数并检查系统状态和错误信息 |

### 4.7 系统健康监控

| ID | 需求 | 验证思路 |
| --- | --- | --- |
| MON-001 | 系统应监控关键 Task 是否保持正常运行 | 人为停止更新关键 Task 的运行标志并观察系统响应 |
| MON-002 | 关键 Task 运行异常时，系统不得继续维持不受监控的电机输出 | 注入 Task 异常并观察电机输出和系统复位 |
| MON-003 | 系统重新启动后应能够提供本次启动的复位原因 | 分别执行上电复位、软件复位和 Watchdog 复位并读取原因 |

## 5. 验证原则


每条需求完成后，应按照表格中的验证思路进行实际测试，并保留能够证明结果的记录。

编译成功只代表代码能够生成固件，不能代替下载和上板验证。根据具体功能，测试证据可以是串口日志、位置或速度曲线、上板观察记录、照片、逻辑分析仪截图以及故障注入结果。
